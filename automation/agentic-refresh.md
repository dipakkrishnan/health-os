# Health OS recurring refresh

This is an owner-approved local automation. Use the exact paths and interpreter
listed below. Before accessing the record, read `skills/refresh/SKILL.md`,
`skills/memory/SKILL.md`, and `skills/memory/references/memory_format.md` from the
installed plugin root.

1. Inspect Health OS status and resync every connection that supports unattended
   refresh. Never start interactive authorization.
2. Verify the repository even if a connection fails. Keep prior data intact and
   treat failures as coverage gaps.
3. Compare the refreshed record with the memory watermark, update cited memory, and
   preserve unresolved conflicts. Do not turn an order into confirmed use or replace
   patient or caregiver reports with model inference.
4. If something actionable changed, write a compact brief under `artifacts/` with
   the change, why it matters, evidence citations, and the next owner or question.
   If nothing actionable changed, do not create an artifact and reply exactly
   `Nothing actionable changed`.

Do not contact anyone, change care, record inferred patient reports, or disclose
record content.
